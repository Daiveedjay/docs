A gate decides whether code meets your project standards. Gate Preview shows whether the current project would pass and which thresholds would fail, without blocking a push or build. Use it to choose realistic settings before you enforce them.

## Opening it

Open **Improve** and choose the gate preview. You can also open **Preview Gate** from the **File tab**.

When a saved project scan is selected, the preview uses that captured result. It shows the saved scope and capture time, and does not rescan current source or spend another project action. Without an earned result, the basic preview checks the current workspace against the presets, respecting your `ignoreFiles` list.

## The six presets

Ordered from most lenient to most strict:

| Preset | Min score | What it's for |
| --- | --- | --- |
| `legacy` | 60 | Large, established codebases with accumulated debt |
| `balanced` | 70 | A typical TypeScript project, and the best starting point |
| `typescript` | 76 | Raises the bar on `any`, `ts-ignore` and missing return types |
| `strict` | 82 | Greenfield code, or a library other teams depend on |
| `ai-assisted` | 82 | Reviewing AI-assisted code at volume. Tightens structural, security, suppression and duplication defaults without imposing a naming convention |
| `security` | 85 | Prioritises secrets and safety. The tightest threshold available |

## What the preview shows

- **Scan average** - a single score across the files in the displayed scope
- **Files analysed** - how many were included
- **Threshold card** - which presets you already pass, and the next one you would fail
- **Recommendation** - the strictest preset you could adopt today with nothing blocked
- **Focus card** - one preset in detail, with controls to step through the others and an **Apply** button
- **Preset grid** - all six at a glance, each clickable

The focus card shows the preset, its minimum score, how many files fail, and their file details when the result is earned or you have Pro access. **Apply** writes `presetId` into `.irisconfig.json` directly, without opening the file.

## Free and Pro

The preview is Free. Opening earned file details does not spend another action. Enforcing a gate at push, build or CI boundaries requires applicable paid access; a preview does not install a hook or prevent a push.

| | Free | Pro |
| --- | --- | --- |
| Gate Preview scan and results | ✓ | ✓ |
| Pass/fail counts per preset | ✓ | ✓ |
| Per-file drilldown with scores | From an earned scan | ✓ |
| Hook enforcement | - | ✓ |

## Acting on the results

**On Free**, add `"presetId": "balanced"` (or whichever preset you chose) to `.irisconfig.json`. The whole team then analyses against the same thresholds. Nothing is blocked yet, but the standard is agreed and committed.

**On Pro**, install the [git hook](/enforcement/git-hook) or the [build gate](/enforcement/build-gate) to start blocking files below your chosen threshold.

**If a large number of files fail**, start at `legacy` or `balanced` and tighten over time rather than adopting the strictest preset immediately. A gate that fails constantly tends to get disabled.

<Note>
  Gate Preview never writes config or blocks anything on its own. Applying a preset is the only action that changes a file, and it requires an explicit click.
</Note>
