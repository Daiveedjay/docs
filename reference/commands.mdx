This page lists the Iris Code commands you can run inside VS Code and editors built on it. Most are in the command palette, the search box for every editor action: open it with <kbd>Ctrl+Shift+P</kbd>, or <kbd>Cmd+Shift+P</kbd> on macOS, then type `Iris Code`. Some commands also appear when you right-click a file or folder.

<Note>
  The commands you type in a terminal are in the [CLI reference](/cli/commands). This page covers the editor.
</Note>

## In the command palette

| Command | Description |
|---|---|
| `Iris Code: Scan Current File` | Scan the file you have open again |
| `Iris Code: Scan Workspace` | Scan all JS/TS/Vue/Svelte/Go/Python/Ruby/C#/Java/Rust files in the workspace |
| `Iris Code: Rescan Everything` | Scan the workspace again, checking every file rather than reusing results for files that have not changed |
| `Iris Code: Scan This File` | Right-click a file in Explorer to scan it |
| `Iris Code: Scan This Folder` | Right-click a folder in Explorer to scan it |
| `Iris Code: Scan Current Folder` | Scan the folder of the currently open file |
| `Iris Code: Open in Panel` | Move the sidebar into a full-size panel beside your code |
| `Iris Code: Open Code Map` | Open a map of your files by health and of which files import which, with [map exports](/features/code-map#exporting-the-map) |
| `Iris Code: Share Report` | Open the [share options](/features/shareable-report) for the saved workspace scan: PNG or SVG card, or PDF report |
| `Iris Code: Install Git Hook` | Install the pre-push hook, a check Git runs before each push. It follows Git's `core.hooksPath` setting, so a Husky project gets `.husky/pre-push` |
| `Iris Code: Uninstall Git Hook` | Remove the Iris Code block from the pre-push hook |
| `Iris Code: Install Build Hook` | Add an Iris Code scan to the project build: a `prebuild` script for Node, or a Makefile target for Go, Python, Ruby and .NET |
| `Iris Code: Uninstall Build Hook` | Remove the Iris Code build hook, leaving any other build steps intact |
| `Iris Code: Write Project Rules for AI Agents` | Write this project's rules for coding agents into `AGENTS.md`, `CLAUDE.md`, a Cursor rule, or Copilot instructions |
| `Iris Code: Open Config Studio` | Open the browser Config Studio to build or edit `.irisconfig.json` |
| `Iris Code: Open Dependents Table` | Open the dependency audit panel: package versions and known security problems (CVEs) |
| `Iris Code: Show Welcome Page` | Open the Getting Started welcome page |
| `Iris Code: Review My Changes` | Scan everything you have changed since your last commit, including new files, and show which files directly import the changed ones. Free |
| `Iris Code: Select Workspace Folder to Scan` | When several project folders are open in one window, choose which one a workspace scan covers |
| `Iris Code: Restart First Scan` | Start the first-scan walkthrough again |
| `Iris Code: Sign In` | Sign in through the browser and refresh the editor licence |
| `Iris Code: Sign Out` | Sign out of the editor. Restrictions set by your organisation that the editor remembered still apply |
| `Iris Code: Check License Status` | Refresh and show the current licence status |
| `Iris Code: Sync Config from Dashboard` | Use a dashboard code to preview and confirm a shared config |
| `Iris Code: Open Trends Table` | Compare your saved workspace scans without scanning again. Older trend history files still work |
| `Iris Code: Lock Trend Baseline` | Use the current workspace snapshot as the trend baseline, the saved starting point later scores are compared with |
| `Iris Code: Clear Trend History` | Remove the current workspace trend history after confirmation |
| `Iris Code: Close Panel` | Close the separate Iris Code panel opened with **Open in Panel** |
| `Iris Code: Add GitHub Actions Workflow` | Generate the Iris Code GitHub Actions workflow |
| `Iris Code: Add CI Pipeline Snippet` | Generate a pipeline snippet for another supported CI provider |
| `Iris Code: Scan Git History for Secrets` | Scan Git history for leaked credentials. Pro |
| `Iris Code: Check Packages Before Agents Install Them` | Choose coding agents and install the free package guard, which checks a package before an agent installs it |
| `Iris Code: Remove the Package Guard Hook` | Remove the package guard entries while preserving other hooks |
| `Iris Code: Rename File to Naming Convention` | Preview and rename one file to its configured naming convention |
| `Iris Code: Undo Last Rename` | Undo the last naming-convention rename |
| `Iris Code: Dependency Network Access` | Choose whether Iris Code may look up package versions and security advisories online |

The [Refactor playbook](/refactor/overview) opens from **Refactor plan** in the File, Folder or Workspace tab. Its panel provides **Get plan**, **Apply mechanical fixes**, **Open agent instructions** and **Verify refactor**.

## Context menus

Iris Code adds entries to the right-click menu in two places in the VS Code interface.

### Explorer (file tree)

Right-clicking in the Explorer, the file list at the side of the editor, lets you scan a file or folder without opening it first:

- Right-click a **JS/TS/Vue/Svelte/Go/Python/Ruby/C#/Java/Rust file** → **Iris Code: Scan This File**
- Right-click a **folder** → **Iris Code: Scan This Folder**
- Right-click **anywhere** in the Explorer → **Iris Code: Scan Workspace**

### Editor (inside a file)

Right-clicking inside an open file lets you scan that file, its folder or the whole workspace:

- **Iris Code: Scan Current File** - re-run analysis on the file you are editing
- **Iris Code: Scan Current Folder** - scan all supported files in the same folder
- **Iris Code: Scan Workspace** - run a full workspace scan from the editor context menu
