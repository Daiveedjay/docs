Iris Code works in several editors, and every one uses the same analysis engine. With the same version and settings, your code gets the same findings and scores wherever you open it.

What differs is the interface around those results. The table below shows which features have been checked in each editor.

## Support matrix

| Feature | VS Code | Forks | JetBrains | Other LSP editors |
|---|---|---|---|---|
| Inline diagnostics | Yes | Yes | Yes | Yes |
| Quick fixes and code actions | Yes | Yes | Yes | Yes |
| Hover: health score and rule id | Yes | Yes | Yes | Yes |
| Code lens on long functions | Yes | Yes | Yes | Host dependent |
| File analysis panel | Sidebar | Sidebar | Tool window | No |
| Workspace and folder scans | Yes | Yes | Yes | No |
| Findings and TODO tabs | Yes | Yes | Yes | No |
| Suppressions, duplicates, naming, dependency and trend tables | Yes | Yes | Yes | No |
| Duplicate diff view | Yes | Yes | Yes | No |
| Review My Changes | Yes | Yes | Yes | No |
| Refactor Playbook panel | Yes | Yes | Yes | CLI or MCP only |
| Code Map tree, graph and exports | Yes | Yes | Yes | CLI graph only |
| Package guard agent hooks | Yes | Yes | Yes | CLI only |
| Opt-in finish verification hooks | Yes | Yes | Yes | CLI only |
| Git and build hook install | Yes | Yes | Yes | CLI only |
| CI workflow generators | Yes | Yes | Yes | CLI only |
| Config sync from the dashboard | Deep link | Deep link | Pasted code | No |
| Rename to naming convention | Yes | Yes | Yes | Yes |
| Git history secrets scan | Yes | Yes | Yes | CLI only |
| Detached panel | Yes | Yes | No | No |
| Guided onboarding tour | Yes | Yes | No | No |
| Explorer file-naming badge | Yes | Yes | No | No |
| Push-blocked counter | Yes | Yes | No | No |

"Forks" means Cursor, Windsurf, VSCodium, Trae and Positron: editors built from VS Code. They install the same extension package as VS Code and behave the same way.

"Other LSP editors" means editors such as Neovim and Helix, which connect to Iris Code through a shared protocol for code-checking tools called LSP, rather than through a full extension.

The CLI, the `iris` commands you type in a terminal, works the same whichever editor you use. `iris check`, `iris gate`, `iris secrets`, hooks and CI all run from a terminal, and they are the same program on every platform.

## One licence, every editor

Signing in once covers every editor and the CLI. There is no per-editor licence or price, and using the same licence from three editors on one machine counts as one user, not three.

VS Code and its forks keep the licence key in the editor's own secure storage. Everything else reads `~/.iris/credentials`, which `iris auth login` writes.

## Other LSP editors

`iris-lsp` is a standalone language server: a small program that runs the whole analysis engine and talks to your editor over LSP. JetBrains support is built on it, and it also works in Neovim, Helix and any other editor that supports LSP.

Ready-to-run programs are published for six platforms, with checksums to verify the download, and need no Node.js installation. [Other LSP editors](/editors/lsp) has the download table, the Neovim and Helix setup, and a clear account of which features are not available outside a full extension.

## Reporting a problem

The same symptom usually has a different cause in each editor, so say which editor and which version you are using. Report it at [iriscode.co/support](https://iriscode.co/support) or email [hello@iriscode.co](mailto:hello@iriscode.co).

## Navigating the extension

VS Code, its compatible forks and JetBrains share the redesigned Iris Code panel. Its main navigation has five areas:

| Area | Where to go |
| --- | --- |
| **Home** | See the open project, current file and the next useful action. |
| **Review** | Review a file or project, inspect Findings and follow TODOs. File, Folder and Workspace choose the review scope. |
| **Improve** | Preview your gate results or open the Refactor Playbook to plan and verify a change. |
| **Explore** | Open Code Map, Schema Graph, Dependency Audit and Trends. Schema Graph needs supported backend schema declarations. |
| **Configure** | Set Configuration, Hooks & CI and Agent rules. Saving rules does not install enforcement. |

Use **Search Iris Code…** to find a tool without remembering its area. The Review scope tabs are **File**, **Folder**, **Workspace**, **Findings** and **TODOs**. On short or narrow panels the scope tabs can scroll out of view to leave room for reading; the main navigation stays available.

Opening a result you already have does not use up an action or rescan changed code. Starting fresh project work checks your allowance first. See [Free allowances](/free).

Other LSP editors show diagnostics and actions through the editor's own interface, not through this panel.
