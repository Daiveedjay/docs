The JetBrains plugin brings Iris Code into IntelliJ IDEA and the other JetBrains IDEs. It runs the same analysis engine and shows the same panel as VS Code, not a cut-down version.

It supports IntelliJ IDEA, WebStorm, GoLand, PyCharm, PhpStorm, RubyMine, Rider and CLion, from 2024.2 onwards.

## Install

<Steps>
<Step title="Install from the Marketplace">
**Settings > Plugins > Marketplace**, search for **Iris Code**, install.
</Step>
<Step title="Restart the IDE fully">
Close and reopen the IDE, rather than only reloading the plugin. The note below explains why.
</Step>
<Step title="Open the tool window">
**View > Tool Windows > Iris Code**, or **Tools > Iris Code: Open Panel**.
</Step>
</Steps>

<Warning>
**Installing from disk does not install the plugins Iris Code needs.** Iris Code relies on another plugin, LSP4IJ, which the Marketplace installs for you. If you install the `.zip` by hand, install LSP4IJ first or Iris Code will not start.
</Warning>

<Warning>
**Restart the IDE fully after installing or updating.** The IDE only learns which file types a plugin handles when it starts. Without a restart it reads `.irisconfig.json` as strict JSON and marks every comment in the file as an error. A restart fixes it.

If the file is still marked after a restart, your IDE may have kept a personal setting from an earlier uninstall that overrides the plugin. Open **Settings > Editor > File Types > JSON5** and add `.irisconfig.json` to its patterns.
</Warning>

## Sign in

Use **Tools > Iris Code: Sign In**, or run `iris auth login` in a terminal. Both write the same `~/.iris/credentials` file, so one sign-in covers the plugin, the CLI (the `iris` terminal commands), your hooks and CI.

## What you get

The tool window is the same panel as the VS Code sidebar, rendered by the same code: Home, Review, Improve, Explore and Configure, with File, Folder, Workspace, Findings and TODOs review scopes, gate preview, trends, and every table. [Panel navigation](/editors/overview#navigating-the-extension) explains where each tool lives. The tables open as editor tabs. Diagnostics (underlines in the code), hover details, code lens hints and quick fixes come through LSP4IJ.

The panel works with the IDE itself:

- clicking a file opens it at the right line
- "Update dependency" runs in a real terminal
- duplicate pairs open in the IDE's own diff viewer
- installing a hook asks before changing your repository

Iris Code actions are available from **Find Action** (`Ctrl+Shift+A`), including **Iris Code: Refactor Plan**. They are all named `Iris Code: ...`, so typing "iris" finds every one of them.

**Refactor plan** in the File, Folder or Workspace tab opens the [Refactor Playbook panel](/refactor/overview). There you can plan a refactor, apply approved mechanical fixes with **Undo**, get instructions for a coding agent, and check the result against the saved starting point (the baseline).

Planning one file is Free; new folder and workspace plans use project access. The **Hooks** section also offers the always-Free [package guard](/agents/package-guard) and the included [finish verification](/refactor/agents#finish-verification).

## What it does not have

- No detached panel. The tool window can be widened or floated using the IDE's own controls.
- No guided onboarding tour. These docs cover the same ground.
- No project-view badge for file-naming violations. The violations still appear in the Problems panel and the naming table.
- No push-blocked counter panel.

Copying your settings from the dashboard works, but through a one-time code you paste rather than a link, because JetBrains IDEs give plugins no way to open from a web link. Use **Tools > Iris Code: Sync Config from Dashboard** and paste the code the dashboard shows you. You see the exact changes and confirm them before anything is written.

## Reporting a problem

When an Iris Code action fails, such as a workspace or folder scan, the IDE notification offers two buttons:

- **Show details** shows the error with the time, the action and the stack trace. The full record is also written to the IDE log (**Help > Show Log in Explorer**, or **Show Log in Finder** on macOS).
- **Report problem** opens a report form on iriscode.co with a short summary already filled in: the Iris Code and IDE versions, your operating system, the action and the error message.

Before the form opens, paths to your home folder and project folder are replaced with `~` and `<workspace>`. The summary travels in the part of the link that browsers do not send to a server, so nothing reaches Iris Code until you review it, add what you were doing and press **Send report**.

## Panel appearance

The panel follows your IDE theme and interface size, including when you switch theme while it is open. If it looks out of step with the rest of the IDE after you change the interface font, close and reopen the tool window to apply the size again.
