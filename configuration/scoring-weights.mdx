Every file gets a health score out of 100, and each finding takes some points off it. A scoring weight is how many points one finding of a given kind takes off.

Custom weights let you make particular findings matter more or less for your project. For example, raising the weight for secrets makes a detected access key lower the score further.

<Note>
Custom weights are available when you are signed in, and do not depend on how many monthly project actions you have left. Set `healthScoreWeights` in `.irisconfig.json`, or use [Config Studio](/configuration/config-studio). Your weights keep applying to the file checks you can run even after your monthly allowance is used up.
</Note>

## What everything costs by default

If you leave a key out, Iris Code uses the value from your preset, or the default below if you have not set a preset.

| Key | Default | What it penalises |
|-----|---------|-------------------|
| `hardcodedSecret` | `10` | Per hardcoded secret found; the largest single deduction |
| `disabledTlsVerification` | `7` | Per disabled-TLS-verification finding |
| `openRedirect` | `7` | Per open-redirect finding |
| `errorWarning` | `5` | Per error-severity structural warning |
| `evalUsage` | `5` | Per eval() / exec() finding |
| `sqlConcatenation` | `5` | Per SQL-built-by-concatenation finding |
| `weakHashing` | `5` | Per weak-hashing (MD5/SHA-1) finding |
| `warningWarning` | `3` | Per warning-severity structural warning |
| `tsIgnore` | `3` | Per `@ts-ignore` comment (TS/JS only) |
| `unsafeRegex` | `3` | Per ReDoS-prone regex finding |
| `duplicateCode` | `3` | Per duplicate code block found in the file |
| `anyUsage` | `2` | Per explicit `any` type (TS/JS only) |
| `deepNesting` | `2` | Multiplier applied to deep nesting score per function |
| `unusedFunction` | `2` | Per unused function definition |
| `insecureRandom` | `2` | Per insecure-RNG finding |
| `debugFlagsEnabled` | `2` | Per debug-flag-enabled finding |
| `bareSuppression` | `2` | Per bare `iris-ignore` comment: a suppression missing its required reason, or naming no valid rule |
| `consoleLog` | `1` | Per console/debug print statement |
| `longParamList` | `1` | Per long parameter list finding |
| `unusedVar` | `1` | Per unused variable |
| `hardcodedLocalhost` | `1` | Per hardcoded-localhost-URL finding |

<Note>
  The nine security smell keys (`evalUsage`, `sqlConcatenation`, `insecureRandom`, `unsafeRegex`, `hardcodedLocalhost`, `disabledTlsVerification`, `debugFlagsEnabled`, `weakHashing`, `openRedirect`) were added alongside [Security Smells](/features/security-smells) detection. The `bareSuppression` key was added alongside [Inline Suppressions](/enforcement/suppressions): a valid suppression with a reason costs nothing, but a bare one is itself a finding. The `duplicateCode` key was added alongside [Duplicate Code Detection](/features/duplicate-detection).
</Note>

## When to customise weights

- Your team ships to a **regulated environment** and wants secrets to cost nearly twice the default: set `"hardcodedSecret": 18`.
- Your codebase is a **prototype** and leftover console logs are not a problem: set `"consoleLog": 0`.
- **TypeScript safety** is the team's top concern: raise `anyUsage` and `tsIgnore` above their preset values.
- You want the health score to reflect only the findings you actually act on: set the others to `0`.

## Security-focused example

Make secrets cost more, and make console logs count for more, for code that has to pass an audit:

```json .irisconfig.json
{
  "presetId": "security",
  "healthScoreWeights": {
    "hardcodedSecret": 18,
    "consoleLog": 3,
    "anyUsage": 2
  }
}
```

## Softening noise for a legacy codebase

Set findings your team has accepted to `0`, so the health score reflects only what you plan to fix:

```json .irisconfig.json
{
  "presetId": "balanced",
  "healthScoreWeights": {
    "consoleLog": 0,
    "unusedVar": 0,
    "unusedFunction": 0
  }
}
```

<Warning>
  Setting a weight to `0` means that kind of finding does **not** affect the health score at all. It still shows in the sidebar, and still appears as an inline warning if those are turned on, but it takes nothing off the 0 to 100 score. Only do this on purpose.
</Warning>

## Interaction with presets

When a `presetId` is set, the preset's own weights are the starting point. Each key you add to `healthScoreWeights` replaces only that one value, and every key you leave out keeps the preset's value. With no preset and no custom weights, the defaults in the table above apply.

## Configuring via Config Studio

Open [Account → Config](https://www.iriscode.co/account/config), switch to **Custom** mode, then expand the **Custom scoring** section. Each weight field shows the preset's value next to it, so you only need to change the keys you care about. Click **Sync to VS Code** when done; only the values you changed from the default are written to the config file.
