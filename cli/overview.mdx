The command-line interface (CLI) lets you use Iris Code by typing commands in a terminal. It can scan code, check packages and run a gate without opening an editor. This makes it useful for scripts, automated checks and developers who prefer the terminal.

## When to use which

The extension is interactive. It scores files as you work and puts findings next to the code you are writing.

The CLI scans, prints a result and returns a status code that another tool can read. Hooks, build scripts and automated pipelines use that code to decide whether to continue.

## Installing

Install the CLI globally with npm:

```bash
npm install -g @iris-code/cli
```

<Note>
  Node 18 or later is required. Run `iris --version` after installation to confirm the package is on your PATH.
</Note>

## Updating

`npm install -g` does not auto-update. If a command you expect is missing (`iris: unknown command: sbom`) or the CLI crashes on exit, you are almost certainly running an old global install - a new npm publish never touches whatever version is already on your PATH. Update it explicitly:

```bash
npm install -g @iris-code/cli@latest
iris --version
```

Confirm the printed version matches the [latest CLI release](https://www.iriscode.co/changelog). If you have multiple Node versions or package managers installed, `which iris` (macOS/Linux) or `Get-Command iris` (PowerShell) shows exactly which install is on your PATH.

## Quick start

<Steps>
  <Step title="Install the CLI">
    ```bash
    npm install -g @iris-code/cli
    ```
  </Step>
  <Step title="Authenticate (opens browser)">
    ```bash
    iris auth login
    ```
    A browser window opens for OAuth sign-in. Your credentials are saved to `~/.iris/credentials` for subsequent commands.
  </Step>
  <Step title="Scan the current directory">
    ```bash
    iris check .
    ```
A single-file check is Free. For a deliberate whole-project inspection, run `iris check . --inspect`; it uses the selected project allowance and records a captured result. A blocking directory check or CI gate requires paid enforcement access.
  </Step>
</Steps>

## Free commands

These commands are available without an Iris Code Pro licence:

- **`iris init`** - set a project up: asks three short questions, recommends a preset, writes `.irisconfig.json`, offers the package guard, creates or refreshes the `AGENTS.md` rules block, and installs the pre-push hook where the licence allows
- **`iris fix --safe <file>`** - remove findings Iris Code can prove are safe to remove, on a single file; previews by default and never writes without confirmation
- **`iris refactor <file>`** - a refactor plan for one file, with `--verify` to compare the result with git HEAD; see the [refactor playbook](/refactor/overview)
- **`iris check <file>`** - single-file health scan; scores and prints findings for one source file
- **`iris graph --focus <file>`** - one file's imports and importers, from the same resolver as the [Code Map](/features/code-map)
- **`iris install` / `iris remove`** - check packages with the [package guard](/agents/package-guard) before installing them, or check a whole cloned project before its install runs; `iris remove` removes packages with the project's package manager
- **`iris secrets`** - scans the whole project for hardcoded secrets, API keys, and tokens; no authentication required
- **`iris security`** - scans the whole project for security smells (eval usage, SQL injection, insecure RNG, weak hashing, and more); no authentication required
- **`iris schema`**: read schema structure or focused-table usage; use `--evidence <evidence-id>` for captured aggregate usage
- **`iris report`** - export an HTML health report, a PNG or SVG card, or a PDF with `--format`
- **`iris config init` / `iris config validate`** - interactively generate `.irisconfig.json` from a preset, or validate an existing one
- **`iris hook git status` / `iris hook build status`** - show whether the git pre-push hook and build hook are currently installed
- **`iris hook agent install|uninstall|status`** - add the package guard hook for Claude Code, Cursor, Codex, GitHub Copilot, Gemini CLI or Windsurf
- **`iris slack setup|test|manifest`** - configure and test Slack notifications sent directly from your own CI
- **`iris rules`** - write this project's configured thresholds into the file your coding agent already reads, generated from `.irisconfig.json`
- **`iris mcp`**: connect agents to basic tools, project actions and owned results; fresh enforcement remains a separate paid capability
- **`iris auth login|status|logout`** - manage authentication credentials

## Project inspection and enforcement

Project inspection commands can use [Free allowances](/free); enforcement commands require applicable paid access. The commands below include both, so choose inspection or saved-result reads explicitly when you do not want to start enforcement:

- **`iris check <dir> --inspect`**: scan a directory using project access, without running paid enforcement
- **`iris check --staged --inspect`**: inspect only files staged in git
- **`iris check --changed --inspect`**: inspect files changed since the last commit
- **`iris deps`** - audit npm, Go, Python, RubyGems, NuGet, Cargo and Maven or Gradle dependencies for outdated versions and known CVEs, with installed versions resolved from your lockfile
- **`iris cve`** - CVE severity gate for CI; exits `1` only when an advisory at or above a chosen severity is found
- **`iris sbom`** - export a CycloneDX 1.5 software bill of materials without registry or advisory lookups
- **`iris todos`** - list every `TODO`, `FIXME`, and `HACK` comment across the project
- **`iris gate`** - the CI gate; exits `1` if `minHealthScore` or any configured `gateMax*` limit is exceeded (see [gate rules](/configuration/irisconfig))
- **`iris graph`** without `--focus` - the whole import graph as text or JSON
- **`iris hook git|build install|uninstall`** - install or remove git pre-push and build hooks
- **`iris hook verify`** - warn in CI when a pushed commit has no pre-push hook record for a Team project; always exits `0`
