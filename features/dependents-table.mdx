A dependency is a package of code written by someone else that your project uses. The Dependents Table shows whether your packages are out of date or have known security vulnerabilities. It brings packages from several languages into one view, so you do not have to check each registry separately.

<Note>
Opening a dependency audit you have already run is Free, and it does not look anything up online again. Your account and workspace access are checked when you are online; results that were confirmed earlier stay readable offline.

Running a fresh audit uses one local project action when it produces a usable result. Looking up package versions and vulnerabilities online still needs your permission first. See [Free allowances](/free).
</Note>

## Opening it

Run **Iris Code: Open Dependents Table** from the command palette. The table compares each package with its public registry, the online catalogue where the package is published, and against the OSV.dev vulnerability database.

## Where it reads from

- **npm** - `package.json`
- **Go modules** - `go.mod`
- **Python** - `requirements.txt` and `pyproject.toml`
- **RubyGems** - `Gemfile.lock`, with `Gemfile` and `.gemspec` fallbacks
- **NuGet** - `.csproj`, `Directory.Packages.props`, `packages.lock.json`, and `packages.config`
- **Cargo** - `Cargo.lock`, with `Cargo.toml` as the fallback for libraries, which conventionally do not commit a lockfile
- **Maven and Gradle** - `pom.xml` and `build.gradle` / `build.gradle.kts`, including Gradle version catalogues in `gradle/libs.versions.toml`

## Versions come from your lockfile

A manifest is a file that lists the packages your project asks for. A lockfile records the exact versions selected, including packages brought in by other packages.

A manifest range like `"express": "^4.18.0"` does not tell you which version is installed. The lockfile does, so it is read in preference when one is present:

- **npm** - `package-lock.json` (v1-v3)
- **pnpm** - `pnpm-lock.yaml`
- **yarn** - `yarn.lock` (classic and Berry)
- **Python** - `poetry.lock` and `Pipfile.lock`
- **RubyGems** - `Gemfile.lock`
- **NuGet** - `packages.lock.json`
- **Cargo** - `Cargo.lock`

An advisory is a published report of a vulnerability. Advisories are then filtered to the version you have installed. A CVE that only affects 3.x is not reported when you are on 4.x, which keeps the list to things you can act on.

How complete the list is depends on the ecosystem:

- RubyGems and Cargo lockfiles include every package, including those brought in by other packages.
- NuGet without `packages.lock.json` checks only the packages your project declares directly.
- Maven and Gradle declarations are read from the build files, not from a full list of installed packages.

A package without one exact version, or with conflicting versions, is marked **not checked**, never assumed clean.

## Monorepos

A monorepo is one repository holding several projects. Workspace members declared through npm or yarn workspaces, or in `pnpm-workspace.yaml`, are found automatically, and their dependencies are combined into a single view, with a repeated package listed once. Internal `workspace:` / `file:` / `link:` dependencies are excluded, since they are your own packages rather than third-party ones.

## What the table shows

For each package, the table displays the installed version, the latest available version, and any known CVEs from the OSV.dev database:

| Package | Installed → Latest | Advisories |
| --- | --- | --- |
| `next` | 14.1.0 → 15.3.2 | - |
| `express` | 4.18.2 → 4.21.2 | CVE-2024-29041 |
| `jsonwebtoken` | 8.5.1 → 9.0.2 | CVE-2022-23529, CVE-2022-23540 |

Each advisory shows a severity badge, the advisory id, a **confidence label**, and the **fixed-in version** where one exists. A package reported in the OpenSSF malicious-packages feed (an advisory id starting `MAL-`) is badged **malicious** rather than by severity, because those reports carry no severity score. To stop such a package being added in the first place, see the [package guard](/agents/package-guard).

A CVE is a public identifier for a known security vulnerability. Advisories describe the affected versions and, where known, which version fixes the problem.

## Confidence labels

A count of vulnerabilities is not much use on its own; what matters is which ones you can fix. Every advisory carries a label saying how you can act on it:

| Label | What it means |
| --- | --- |
| `fix-available` | A patched version exists. Upgrading resolves it |
| `direct` | The vulnerable package is one you depend on directly, so the upgrade is yours to make |
| `transitive` | It arrived through another dependency, so a fix may depend on that package's maintainer |
| `manual-review` | The advisory could not be matched confidently to your installed version. Review it yourself |

## Unverifiable advisories are never shown

An advisory record without an id or severity that can be checked is dropped rather than shown, and the footer says how many were skipped. Duplicate records describing the same underlying advisory are collapsed into a single row.

If a lookup fails outright, through a network error or a registry outage, that package is marked **not checked** rather than assumed clean. "No vulnerabilities found" and "the check did not complete" mean different things, and the table distinguishes them.

## The sidebar badge

The Dependencies section of the Workspace tab shows a summary of your last scan: green when it came back clean, otherwise the number of vulnerable packages and the highest severity found.

It reads only from the local cache, so opening the sidebar never triggers a network request on its own. Refresh it from the Dependents Table, or by running `iris deps`.

## Caching

Results are cached for 24 hours, so reopening the panel is immediate. The cache is kept per user, under `~/.iris/cache/`, and never inside the project: a cache file committed to a repository could otherwise decide what a scan reports. Iris Code does not write into your project or its `.gitignore` for this.

## No token required

Vulnerability lookups query OSV.dev directly. There is nothing to create, no rate limits to manage, and no token to configure.

Each lookup sends a package name, its ecosystem and a version. It does not send your code, your file paths, or your project name.

<Tip>
  A failed advisory lookup does not prevent the table loading. Version data still appears, and the affected package is marked "not checked" so its advisory status is explicit.
</Tip>
