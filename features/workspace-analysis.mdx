A workspace scan checks the supported files in your open project folder together. It gives you a project-wide view of health scores and findings, so you can choose where to start. Files excluded by your settings are left out of that view.

## Running one

**Iris Code: Scan Workspace** from the command palette, or open **Review → Workspace** and use **Scan Workspace**. It walks every supported file and gives you:

- **Readiness** - the top-level score, blockers, warnings, TODO load and trend
- **The totals** - files, directories, lines, functions
- **A language breakdown**
- **Hotspots** - the five biggest files and the five most complex
- **Unused packages** - declared in `package.json`, `go.mod`, `requirements.txt` or `pyproject.toml`, never imported
- **A CVE badge** on the Dependencies section, green when the last cached dependency scan found nothing, otherwise the count and worst severity. It reads the local cache only and never goes to the network on its own. See [Dependents Table](/features/dependents-table)
- **Findings** - every blocker and warning in one list
- **TODOs** - grouped by type
- **A file tree** you can click through
- **Trends** - the score delta plus your three most improved and three most regressed files

<Note>
Saved results retain their captured scope, configuration, time and coverage. They describe that scan, not later file changes. Opening a result does not refresh it. A deliberate fresh scan can use one local project action; [Free allowances](/free) explains reuse, exhaustion and offline reads.
</Note>

<Tip>
  Results are cached, so you can leave the Workspace tab and come back without scanning again.
</Tip>

## Just one folder

Right-click any folder in the Explorer and pick **Iris Code: Scan This Folder**. Or hit **Scan Current Folder** in the Folder tab to scan whatever the open file lives in.

The **Folder** tab shows the same stats, chart, rankings and tree as the workspace, with its own Rescan and Clear.

<Note>
Basic file checks stay Free. Signed-in Free users can run fresh workspace, folder and changed-file scans within their monthly project allowance. A completed usable scan uses one action; opening its views does not use another. Pro provides applicable unmetered local work and continuous enforcement.
</Note>

## Scanning again

An unchanged captured project input can reuse its earned result without another local action. Changes to source, effective settings, scope, engine or baseline require a matching fresh input identity. A usable fresh scan counts as one project action, not one action per file. Totals, duplication and unused-package conclusions describe the captured scope rather than files changed after that scan.

**Rescan everything** deliberately bypasses reuse and starts fresh work after checking access. It can consume one action on Free when it produces a usable result. Opening a saved result, changing views or exporting it does not start that scan.

Older pre-launch editor paths also have an in-memory per-file cache. Their notification can say “Analysed 1 file, reused 3 unchanged.” That describes engine work within a scan, not the monthly counter. Those cached file results are discarded when the editor closes; earned results are stored separately and survive restart.

## Findings and TODOs

Both tabs fill from your most recent scan, whether that was a folder or the whole workspace. A label at the top tells you which ("Showing: folder · src"), with one click back to workspace-wide, so you're never reading folder results thinking they're the whole project.

Each row gives you a severity dot, the file and line, and what's wrong. Click it to land there.

The Findings badge shows errors in red, or the total when there are none. The TODOs badge counts everything. Findings stay put until you rescan or clear.

## Trends

Open **Trends** to compare saved whole-workspace reviews. Earned reviews stay available after your allowance runs out or paid access ends. Opening a comparison does not scan current source or spend another action.

Choose two capture times to see per-file score changes. Each review keeps the settings and engine identity used when it was captured. If those differ, the comparison warns you: a score change can reflect a different standard, not just a code change. Folder and changed-file reviews are excluded from whole-workspace trends.

Earned reviews are private to the account that captured them and the bound workspace context. Sign in to that account to reopen them. Previously earned results can be read offline after that account has been validated on this machine.

Existing rolling trend files remain supported:

- They live in `.iris-snapshots/` at your project root, which is added to `.gitignore`.
- Legacy scans update one snapshot per day. Free keeps two rolling snapshots; Pro keeps the rolling history.
- **Clear trend files** removes those rolling snapshots and the locked baseline. It does not delete private earned reviews.
- Locking a baseline for automatic regression enforcement remains a paid feature.

## Sharing a report

A completed workspace scan can be shared as a summary card or a PDF report. Select the download icon in the Iris Code sidebar header, or run **Iris Code: Share Report** from the command palette, to open the export options.

The card leaves out file paths, source code and secret values, so it is safe to post or attach to a pull request. [Shareable scan reports](/features/shareable-report) explains each format and what the numbers mean.

From the terminal:

```bash
iris report
```

Writes `iris-report.html` to the current directory. `--output <path>` chooses a different destination. A fresh directory scan uses project access; use `--evidence <evidence-id>` to export an owned captured result without rescanning.

<Note>
You can also share an earned scan as a [card or PDF](/features/shareable-report). Saved exports remain available after allowance exhaustion or paid access ends.
</Note>
