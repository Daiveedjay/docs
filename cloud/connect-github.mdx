Cloud scans need to read your code, so Iris Code connects through a GitHub App: a small integration you install on GitHub and point at the repositories you choose. It asks only for the permissions a scan needs, and it can only read, never change anything.

## Installing

<Steps>
  <Step title="Open Projects in your account">
    Personal repositories live under **Projects**. A team's live under that team's **Projects**.
  </Step>
  <Step title="Choose Connect GitHub">
    You are sent to GitHub to install the Iris Code App.
  </Step>
  <Step title="Pick the repositories">
    Select individual repositories rather than granting access to all of them, unless you really want every repository to be scannable. You can change the selection on GitHub at any time.
  </Step>
  <Step title="Import a repository">
    Back in Iris Code, choose a repository to import. One audit starts straight away, on the latest commit of the default branch.
  </Step>
</Steps>

## What the App can read

Three read-only repository permissions, and nothing else:

| Permission | Access | Why |
| --- | --- | --- |
| **Contents** | Read | Download the source tarball for the commit being audited |
| **Pull requests** | Read | Know that a PR was opened or updated, and which commit is at its head |
| **Metadata** | Read | Mandatory for every GitHub App; repository name and default branch |

There is no write permission of any kind. Iris Code cannot push, comment, open a pull request, change a setting or alter a branch. It cannot read your issues, actions, secrets or members.

## What it subscribes to

The App asks GitHub to tell it about these events:

- **Push** - only for the default branch. A push to any other branch is ignored, so work on feature branches never starts a cloud scan
- **Pull request** - opened, reopened, and synchronised (a new commit pushed to the branch)
- **Installation** and **Installation repositories** - so that removing access, suspending the App or deselecting a repository stops audits straight away

<Note>
  Deselecting a repository on GitHub, suspending the App or uninstalling it all remove Iris Code's access immediately. Audits waiting to run for that repository are cancelled and do not count against your allowance.
</Note>

## What leaves your machine, and what leaves GitHub

For a cloud scan, Iris Code's scanner fetches the source from GitHub, analyses it and throws it away. What is stored is the report: scores, finding counts, severities, file paths and the list of packages your project uses.

This is different from the editor, where analysis happens on your machine and nothing is uploaded. If you would rather no source was ever fetched, do not connect a repository. The editor and the CLI work exactly as before.

## Reconnecting

Reconnecting a repository you had disconnected starts from scratch: its earlier cloud reports were deleted when you disconnected it and cannot be recovered.

Losing access is different. If a repository only lost access, because the App was revoked or the repository was deselected, its audit history is kept and carries on once access returns.

## Troubleshooting

### A repository shows 'allowance used'

The account or team has used its scan allowance for the period. Automatic audits start again on their own when it resets. The GitHub connection itself is fine. See [Scan allowances](/cloud/allowances).

### A repository shows the connection needs attention

Iris Code's access to that repository ended. Either it was deselected on GitHub, the App was suspended or uninstalled, or the repository was renamed or moved. Reconnect from GitHub and audits resume, with history intact.

### Pushes are not triggering audits

Check these three things, in order:

1. The push was to the **default branch**, since other branches are ignored.
2. **Audit merges** is on for that repository.
3. The repository is not paused. Pausing stops every automatic audit, while manual ones still work.

### An audit has been queued for a long time

If no scanner has picked up an audit within fifteen minutes, it is reported as stalled rather than slow, because nothing is running it. Cancel it so the commit can be tried again. A cancelled audit does not count against your allowance.
