This guide takes you from installing Iris Code to checking your first file and your whole project. You will see a health score, a number from 0 to 100, and a list of findings that explain what needs attention.

Everything on this page is free and works without an account.

<Steps>
  <Step title="Install it">
    <Tabs>
      <Tab title="VS Code and forks">
        Press `Ctrl+Shift+X` (or `Cmd+Shift+X`), search for **Iris Code**, and click Install. Its icon appears in the Activity Bar, the strip of icons down the side of the editor; click it to open the sidebar.

        The same search works in **Cursor**, **Windsurf**, **VSCodium** and **Trae**, which install the identical build from [Open VSX](https://open-vsx.org/extension/davidjaja/iris-code). You can also [install the `.vsix` file manually](/installation).
      </Tab>
      <Tab title="JetBrains IDEs">
        Install **LSP4IJ** first, a free plugin Iris Code needs to talk to the IDE. Then open **Settings → Plugins**, go to the Marketplace tab, search for **Iris Code** and click Install.

        Afterwards, restart the whole IDE, not just the plugin. JetBrains registers file types only at startup, and skipping the restart is the most common reason Iris Code looks broken on the first day.

        Open the **Iris Code** tool window from the right sidebar. It works in IntelliJ IDEA, WebStorm, PyCharm, GoLand, PhpStorm, Rider, RubyMine, CLion and Android Studio. [More detail here](/editors/jetbrains).
      </Tab>
    </Tabs>

    <Note>
      Every editor uses the same checks underneath, so a file gets the same score and the same findings wherever you open it.
    </Note>
  </Step>

  <Step title="Open a supported file">
    Open a JavaScript, TypeScript, Vue, Svelte, Go, Python, Ruby, C#, Java or Rust file. Iris Code scores it automatically; you do not need to run anything.

    Open **Review → File**. The **File tab** shows:

    - **A readiness summary** - the score, the number of blockers, whether a hook is installed and how the score has changed over time
    - **The health score** - 0 to 100, recalculated every time you save
    - **Blockers and warnings** - click one to jump to its line in the file
    - **Every function** - with its length and complexity, meaning how hard it is to follow
    - **Code smells** - patterns that make mistakes more likely, such as TODOs, magic numbers, debug prints, unused variables and long parameter lists

    Save the file and the score updates immediately.
  </Step>

  <Step title="Run your free workspace scan">
    Open the command palette (`Ctrl+Shift+P` / `Cmd+Shift+P`) and run **Iris Code: Scan Workspace**. The workspace is the project folder open in your editor.

    Iris Code checks every supported file and fills in:

    - **Workspace readiness** - one score for the whole project, with blocker and warning counts
    - **Hotspots** - the largest and most complex files, ranked first
    - **Findings tab** - every blocker and warning in one list you can filter
    - **TODOs tab** - every TODO, FIXME and HACK comment in the project

    Your first full workspace scan stays on your machine and needs no account. To run project scans every month, sign in. Results you already have stay available without scanning again; see [Free allowances](/free).

    <Note>
      That first result is a snapshot of the project at the moment you scanned it.

      After it, each new workspace or folder scan uses one local project action, if your account has an allowance. Opening findings, TODOs, maps or reports you already have does not use another one.

      - Hooks, builds and CI enforcement need a paid plan.
      - The package guard, which checks packages before a coding agent installs them, stays Free.
      - Verification that comes with a refactor plan you already have stays Free.
    </Note>
  </Step>

  <Step title="Preview what would be blocked">
    At the bottom of the **File tab**, click **Preview Gate**. Iris Code scans the project in the background and shows how it scores against all six presets. A preset is a ready-made set of standards.

    | Preset | Min score | Best for |
    |---|---|---|
    | **Legacy** | 60 | Large, established codebases with accumulated debt |
    | **Balanced** | 70 | A typical TypeScript project, and the best starting point |
    | **TypeScript** | 76 | Raising the bar on type safety |
    | **Strict** | 82 | Greenfield code, or a shared library |
    | **AI-assisted** | 82 | Reviewing AI-assisted code at volume, without imposing a naming convention |
    | **Security** | 85 | Prioritising secrets and safety |

    Each card shows how many files would be blocked at that minimum score. **Apply** saves your choice as `presetId` in `.irisconfig.json`, the project's settings file, without opening it.

    <Note>
      Preview Gate is free and changes nothing. No hook is installed and no file is blocked until you turn blocking on yourself. Pro adds the list of which files fail each preset, and by how much.
    </Note>
  </Step>

  <Step title="Install the CLI (optional)">
    The CLI is the set of Iris Code commands you type in a terminal. Use it to scan, to check code in CI (the automated checks that run after a push) or to audit your packages without opening an editor:

    ```bash
    npm install -g @iris-code/cli
    iris --version
    ```

    The CLI runs the same checks as the extension, so it uses the same thresholds. `iris check <file>` scores a single file, and `iris gate` is the command to use in CI.
  </Step>
</Steps>
