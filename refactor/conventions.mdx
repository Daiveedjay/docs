A convention is the way your project already organises its code, such as keeping types in a types folder. Iris Code looks for these patterns so a refactor fits your project rather than introducing a different layout.

## Detected evidence

| Convention | Used by |
|---|---|
| Constants location | Constant extraction and named numeric values |
| State library | State consolidation |
| File naming | Proposed module names |
| Components, hooks and utils layout | Cluster and component destinations |
| Barrel modules | Export wiring instructions |
| Test placement | Related test moves |
| Native package, namespace or module layout | Go, Python, Ruby, C#, Java and Rust moves |
| Type location | Type moves |

Iris Code only calls a layout a detected convention when at least three different files support it and more than 60% of the relevant files follow it. Exactly 60% is not enough.

For example, four of five relevant files following the same layout can qualify; two of two cannot. Without enough evidence, the result says **No project convention detected** and labels the suggested location `proposal`, so you know it needs review.

| Origin | Meaning |
|---|---|
| `detected` | The repository evidence meets both thresholds |
| `configured` | A `refactor.destinations` override wins over detection |
| `proposal` | There is insufficient evidence; review the suggested location |

## Configuration

```json
{
  "refactor": {
    "destinations": {
      "constants": "src/shared/constants",
      "types": "src/types",
      "components": "src/components",
      "hooks": "src/hooks",
      "utils": "src/utils"
    }
  }
}
```

Each path starts from your project folder and must stay inside it. These locations belong to that project, so Config Studio does not include them; syncing settings keeps the values already in the destination project.

Vue and Svelte keep their component layout. Their language settings come from the language declared in the component's script.
