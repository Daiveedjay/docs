An AI assistant can change fourteen files in one prompt. Reviewing that properly takes longer than most people have, so the diff gets skimmed and approved.

Iris Code reviews it deterministically instead. It scores every file, flags the hardcoded key, the function that has doubled in length, and the block now pasted in three places, and it can block the push before any of it leaves your machine.

It makes no judgement about who wrote the code. It checks what is there.

<Note>
  Iris Code does not attempt to identify AI-generated code, and it does not upload your source. Analysis runs on your machine, in your editor, in milliseconds. No model processes your files.
</Note>

## What you get

**A score on every file, on every save.** Zero to 100, reduced by long functions, deep nesting, leftover debug prints and hardcoded values. Nothing needs triggering.

**Secrets caught before they ship.** A real API key is flagged in the sidebar with its value masked. Free on every plan, no configuration required.

**Copy-paste made visible.** When the same block appears in three files, Iris Code reports all three locations and can open them side by side.

**A gate you turn on when you are ready.** Preview how your project scores against five presets first. When the result looks right, a pre-push hook or a CI step blocks anything below your threshold.

## How it works

<Steps>
  <Step title="Install the extension">
    Install [Iris Code](https://marketplace.visualstudio.com/items?itemName=davidjaja.iris-code) from the Marketplace. It is free, and the icon appears in your Activity Bar immediately.
  </Step>
  <Step title="Open a file">
    JavaScript, TypeScript, Vue, Svelte, Go, Python, Ruby or C#. The score appears in the sidebar with the findings below it. No configuration required.
  </Step>
  <Step title="Preview your enforcement posture">
    At the bottom of the File tab, click **Preview Gate**. It shows how your code scores against every preset without changing anything.
  </Step>
  <Step title="Enable enforcement">
    Install the pre-push hook, or add `iris gate` to CI. Code below your threshold is then blocked before it ships.
  </Step>
</Steps>

## Your code stays on your machine

Analysis runs in the editor process, on your machine. Your source never reaches a server of ours, and no AI model processes it.

Iris Code does make network requests, and it is worth being specific about which: signing in, licence validation, dependency version and advisory lookups, and anonymous product-use events you can disable in your account settings. None of them carry source code, file contents or project structure.

That local-first design gives you three things:

- **Instant feedback** - milliseconds on save, with no round trip.
- **Offline capability** - file analysis and CLI commands work without a connection.
- **Privacy by design** - proprietary code, secrets and unreleased features stay on your machine.

## Languages

| Language | Extensions | Worth knowing |
|---|---|---|
| **TypeScript** | `.ts`, `.tsx`, `.mts`, `.cts` | Also flags `any`, `@ts-ignore`, non-null assertions, missing return types |
| **JavaScript** | `.js`, `.jsx`, `.mjs`, `.cjs` | Full smell and complexity analysis, plus unused imports |
| **Vue** | `.vue` | `<script>` and `<script setup>`, analysed as TypeScript when `lang="ts"` is set. Template and style are excluded |
| **Svelte** | `.svelte` | Instance and module `<script>`, with the same `lang` handling. Markup and style are excluded |
| **Go** | `.go` | Functions and methods, unused `go.mod` packages, with `vendor/` skipped |
| **Python** | `.py`, `.pyw` | `def` declarations, unused packages from `requirements.txt` or `pyproject.toml`, with `.venv` skipped |
